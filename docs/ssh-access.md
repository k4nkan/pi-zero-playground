# Pi に SSH で入る（メンバー向け）

メンバーが自分の鍵を作り、公開鍵を管理者に送り、管理者が Pi に登録すると、`ssh kanta@<PiのIP>` でパスワードなしに入れる。

- ログインするユーザーは全員 `kanta` を共有する。誰の鍵かは、鍵に付けた名前（`taro@lab` など）で見分ける
- 入り方は鍵認証だけ。登録されていない PC からは入れない
- 研究室の LAN（Wi-Fi か有線）につないでいる必要がある
- Pi の IP は、Pi の画面のログイン表示に出る

## 流れ

| # | 誰が | やること |
| --- | --- | --- |
| 1 | メンバー | 鍵を作る（最初の 1 回だけ） |
| 2 | メンバー | 公開鍵（`.pub`）を管理者に送る |
| 3 | 管理者 | Pi の `~/.ssh/authorized_keys` に登録する |
| 4 | 管理者 | Pi の IP を伝える |
| 5 | メンバー | `ssh kanta@<PiのIP>` でつなぐ |

## 1. 鍵を作る（メンバー）

Mac はターミナル、Windows 10 以降は PowerShell で実行する。`taro` は自分の名前に置き換える。

```sh
ssh-keygen -t ed25519 -C "taro@lab"
```

1. 保存場所を聞かれたら、そのまま Enter
2. パスフレーズを入れる（PC をなくしても鍵を使われにくくなるので、付けるのがおすすめ）
3. `~/.ssh/id_ed25519`（秘密鍵）と `~/.ssh/id_ed25519.pub`（公開鍵）ができる

すでに `~/.ssh/id_ed25519` がある人は、作り直さずにそれを使う。上書きすると、その鍵で入っていた他のサーバーに入れなくなる。

## 2. 公開鍵を送る（メンバー）

```sh
cat ~/.ssh/id_ed25519.pub
```

出てきた `ssh-ed25519 AAAA... taro@lab` の 1 行を、Slack などで管理者に送る。

- 送ってよいのは `.pub` が付いたほうだけ
- `.pub` が付いていない `id_ed25519` は秘密鍵。誰にも渡さない・どこにも貼らない

## 3. Pi に登録する（管理者）

受け取った 1 行を、Mac から `authorized_keys` の末尾に足す。

```sh
ssh kanta@<PiのIP> 'echo "ssh-ed25519 AAAA... taro@lab" >> ~/.ssh/authorized_keys'
```

- `>>`（追加）を `>`（上書き）と間違えない。`>` にすると、管理者を含む全員の鍵が消える
- 行の末尾の名前で、誰の鍵か分かるようにしておく

登録済みの鍵の一覧（指紋と名前だけで、鍵そのものは出ない）:

```sh
ssh kanta@<PiのIP> 'ssh-keygen -lf ~/.ssh/authorized_keys'
```

## 4. IP を伝える（管理者）

Pi の画面に出ている IP を伝える。ルーターで DHCP 予約をしているなら、その固定の IP。

## 5. つなぐ（メンバー）

```sh
ssh kanta@<PiのIP>
```

- 初回は「このホストを信用するか」と聞かれるので `yes`
- パスワードを聞かれずに `kanta@kanta:~ $` が出れば成功

毎回 IP を打つのが面倒なら、自分の `~/.ssh/config` に書いておくと `ssh peace-cam` だけでつながる。

```
Host peace-cam
  HostName <PiのIP>
  User kanta
```

`kanta@kanta.local` の `@` の前はユーザー名、後ろは接続先（Pi のホスト名に `.local` を付けたもの）。研究室の LAN では `.local` の名前が引けないことがあるので、IP で指定するほうが確実。

## 抜けるとき（管理者）

その人の名前が付いた行を消す。

```sh
ssh kanta@<PiのIP> 'sed -i "/taro@lab$/d" ~/.ssh/authorized_keys'
```

## つながらないとき

| 症状 | よくある原因 |
| --- | --- |
| `Could not resolve hostname` | `.local` の名前が引けていない。IP で指定する |
| `Connection timed out` | 研究室の LAN にいない、IP が変わった、Pi が落ちている。Pi の画面で IP を確認する |
| `Permission denied (publickey)` | 鍵が登録されていない、または別の鍵を使っている。`ssh -v` で使われた鍵を見て管理者に伝える |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | Pi を焼き直した、または同じ IP に別の機器が来た。管理者に確認してから `ssh-keygen -R <PiのIP>` |

## 使うときのルール

- **カメラは同時に 1 プロセスだけ**。ピースカメラ・映像だけモード・配信のどれかが動いていると、ほかは使えない。コンソールの状態表示で確かめてから使う
- **メモリは 512MB しかない**。MediaPipe などの重い処理を 2 人が同時に動かすと Pi が固まり、SSH も届かなくなる。重い処理は 1 人ずつ
- **コードは Pi 上で直接編集しない**。このリポジトリで変更して、Mac から `rsync` で送る
- `sudo`・ファイル削除・パッケージの導入や更新・再起動は、ほかのメンバーに声をかけてから
